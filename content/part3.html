Classification by probability

Instead of drawing a boundary through the feature space, naive Bayes asks a direct question: given these feature values, which class is more probable? It answers with Bayes' theorem and one very strong assumption.

\[ P(C_k \mid x) = \frac{P(x \mid C_k)\,P(C_k)}{P(x)} \]
TermNameWhere it comes from
\(P(C_k \mid x)\)PosteriorWhat we want — probability of the class given the features
\(P(x \mid C_k)\)LikelihoodEstimated from training data, per class
\(P(C_k)\)PriorClass frequency in the training data
\(P(x)\)EvidenceThe same for every class, so it cancels when comparing

Because the denominator is identical for all classes, classification only needs the numerator:

\[ \hat{y} = \arg\max_k \; P(C_k)\prod_j P(x_j \mid C_k) \]

The naive assumption

Conditional independence

The features are assumed independent of each other given the class. This lets the joint likelihood factorise into a product of one-dimensional terms, which is why the model needs so little data and is so fast.

The assumption is almost always false — humidity and outlook are not independent in weather data. The remarkable empirical fact is that classification often still works, because the model only needs the correct class to have the highest score, not the scores themselves to be accurate.

Predict for Outlook = Sunny, Temperature = Cool, Humidity = High, Wind = Strong

The zero-frequency problem

If a feature value never appears with a class in training, its likelihood is zero, and the product collapses to zero regardless of everything else. One unseen combination destroys the prediction.

Laplace smoothing fixes it by adding a small count to every cell:

\[ P(x_j \mid C_k) = \frac{\text{count}(x_j, C_k) + \alpha}{\text{count}(C_k) + \alpha \cdot |V_j|} \]

where \(|V_j|\) is the number of distinct values of feature \(j\). With \(\alpha = 1\) no probability is ever exactly zero.

Continuous features

The frequency-table approach only works for categorical features. For a continuous feature, assume it is normally distributed within each class and use the density:

\[ P(x \mid C_k) = \frac{1}{\sqrt{2\pi\sigma_k^2}}\exp\left(-\frac{(x-\mu_k)^2}{2\sigma_k^2}\right) \]

Estimate \(\mu_k\) and \(\sigma_k\) from the training rows of class \(k\). This is Gaussian naive Bayes.

Check your understanding

Why is Laplace smoothing needed?
Because the likelihoods are multiplied, one factor of zero annihilates the score no matter how strong the rest of the evidence. Adding a small count to every cell guarantees no factor is ever exactly zero.

What a decision tree is

A decision tree classifies by asking a sequence of yes/no questions about the features. Each internal node is a question about one attribute, each branch is one of that attribute's values, and each leaf carries a predicted class.

Definition

A decision tree is a tree-structured plan of attribute tests in which each path from root to leaf corresponds to a conjunction of attribute tests, and the leaf gives the classification for all instances satisfying that conjunction.

Learning the tree means deciding which question to ask first at each node. There are two attributes you could split on and both produce a valid tree — the algorithm needs a criterion to choose between them. That criterion is built from entropy.

Entropy — the impurity of a node

Entropy measures how mixed a set of class labels is. If a node contains only one class it is pure and carries no uncertainty; if it is an even mixture the uncertainty is maximal.

\[ H(S) = -\sum_{i=1}^{c} p_i \log_2 p_i \]

where \(p_i\) is the fraction of examples in \(S\) belonging to class \(i\), and \(c\) is the number of classes. Every symbol:

SymbolMeaning
\(S\)The set of training examples at this node
\(c\)Number of distinct classes (2 for Yes/No)
\(p_i\)Proportion of \(S\) in class \(i\), so \(\sum p_i = 1\)
\(\log_2\)Base 2, so the result is measured in bits

For a two-class problem the curve is a single hump:

  • All one class (\(p = 1\) or \(0\)): \(H = 0\). The node is pure — asking anything further gains nothing.
  • Half and half (\(p = 0.5\)): \(H = 1\) bit. Maximum uncertainty for two classes.
  • The curve is symmetric about 0.5 and never exceeds 1 for two classes.

Entropy explorer

Information taken

This is the step that is easy to skip and impossible to do the rest without. Once you split a node on an attribute, the parent set \(S\) is broken into smaller subsets \(S_1, S_2, \ldots, S_v\), one per value of that attribute. Each subset has its own entropy. To compare the split against the parent you need one number for all of them, so you take the weighted average, weighting each branch by how many examples fell into it.

Definition — information taken

The information taken by an attribute \(A\) is the total entropy that remains in the branches after splitting on \(A\), weighted by branch size:

\[ \text{InfoTaken}(S, A) = \sum_{v \in \text{values}(A)} \frac{|S_v|}{|S|}\, H(S_v) \]

Equivalently: the average number of bits still needed to classify an example once you know its value of \(A\).

Every symbol again:

SymbolMeaning
\(A\)The attribute being tested, e.g. Outlook
\(v\)One of its values, e.g. Sunny
\(S_v\)The subset of \(S\) whose examples have value \(v\)
\(|S_v| / |S|\)The weight — the fraction of examples going down that branch
\(H(S_v)\)The entropy still present inside that branch

Two properties are worth stating because they explain everything that follows. The weights sum to 1, so information taken is itself a weighted average of entropies and therefore also lies between 0 and \(\log_2 c\). And because a split can never increase total impurity, information taken is always less than or equal to \(H(S)\) — you never lose information by splitting, you only sometimes fail to gain much.

Information gain — the difference

Definition — information gain

The information gain of an attribute is what the split took away:

\[ \text{Gain}(S, A) = H(S) - \text{InfoTaken}(S, A) \]

So the three quantities fit together as: entropy before, minus information taken (what remains), equals information gained (what was removed). An attribute with information taken equal to \(H(S)\) has gain 0 — it told you nothing. An attribute that leaves every branch pure has information taken 0 and gain equal to the whole of \(H(S)\) — a perfect split.

Why "gain" and not just "lowest entropy"

Comparing raw branch entropies across attributes with different numbers of values is misleading. An attribute with many distinct values produces many tiny branches, each easily pure, so its unweighted average entropy looks excellent while it has learned nothing general. The weighting by \(|S_v|/|S|\) is what corrects for this, which is why a unique ID column does not automatically win.

Decision. Wind wins outright and both branches are pure:

  • Wind = Weak → days 4, 5, 10, all Yes → leaf Yes
  • Wind = Strong → days 6, 14, both No → leaf No

Notice that Temperature and Humidity are tied at 0.0200 and neither is chosen. A tie would be broken arbitrarily — by attribute order, or by a secondary criterion such as Gini.

Gini impurity — the alternative criterion

CART uses a different impurity measure. It is cheaper to compute because it needs no logarithms.

\[ \text{Gini}(S) = 1 - \sum_{i} p_i^2 \]

For two classes this is \(2pq\), which peaks at 0.5 when the split is even and is 0 when the node is pure.

The same root split scored with Gini

Parent: \(\text{Gini}(S) = 1 - (9/14)^2 - (5/14)^2 = 1 - 0.4133 - 0.1276 = 0.4592\)

Branches:

  • Sunny (2, 3): \(1 - 0.16 - 0.36 = 0.48\)
  • Overcast (4, 0): \(1 - 1 - 0 = 0\)
  • Rain (3, 2): \(1 - 0.36 - 0.16 = 0.48\)

Weighted (the Gini analogue of information taken): \(\frac{5}{14}(0.48) + \frac{4}{14}(0) + \frac{5}{14}(0.48) = 0.3429\)

Gini gain \(= 0.4592 - 0.3429 = \mathbf{0.1163}\)

Different number from the entropy gain of 0.2467, same conclusion: Outlook is the best split. The two criteria disagree only rarely, and when they do the effect on accuracy is small.

Pruning

An unconstrained tree grows until every leaf is pure, which memorises the training data — the training set above would be classified perfectly and generalise poorly. Two remedies:

  • Pre-pruning — stop early: cap the depth, require a minimum number of examples per leaf, or refuse splits whose gain falls below a threshold.
  • Post-pruning — grow the full tree, then remove branches that do not improve accuracy on a validation set. More expensive and usually better, because it only removes what was actually useless.
Exam trap

Information gain is biased toward attributes with many distinct values. A unique identifier column would split every example into its own pure leaf, giving a gain of exactly \(H(S)\) — the maximum possible — while being completely useless. This is why real implementations impose a minimum samples-per-leaf alongside the gain criterion.

Check your understanding

A node has 10 positives and 10 negatives. Its entropy is 1 bit. After splitting on an attribute, the weighted average branch entropy is 0.4. What is the information gain?
Gain = entropy before − information taken = 1.0 − 0.4 = 0.6 bits. The 0.4 is the information remaining in the branches; the gain is what the split removed.
On the Sunny branch, Humidity gave a gain of 0.9710 and Temperature gave 0.5710. Why was Humidity chosen?
Humidity's information taken was 0 — High gave three No, Normal gave two Yes — so its gain equalled the full branch entropy of 0.9710. Temperature left one branch impure (Mild was 1 Yes, 1 No), so 0.4000 of information remained and only 0.5710 was gained. There was no tie; the gap is large.
Why does the Overcast branch become a leaf immediately, at depth 1?
A node with entropy 0 is pure and cannot be improved — any further split would produce children that all predict the same class, adding nodes without adding information. The recursion stops on purity, not on depth or on running out of attributes (although that is the other stopping condition, handled by taking a majority vote).

The laziest classifier

KNN does no training at all. It stores the entire dataset and, at prediction time, finds the \(k\) closest training points and takes a vote. That is the whole algorithm.

Algorithm
  1. Store all training points and their labels.
  2. For a new point, compute the distance to every stored point.
  3. Take the \(k\) smallest distances.
  4. Classification: majority vote among their labels. Regression: average their values.

This is called a lazy learner: it defers all work to prediction time. Training is \(O(1)\), but each prediction costs \(O(n \cdot d)\) for \(n\) points in \(d\) dimensions.

The distance metric

\[ d(a,b) = \sqrt{\sum_{j=1}^{d}(a_j - b_j)^2} \]

Euclidean distance. Because it sums squared differences across features, features must be scaled first — otherwise a feature measured in thousands dominates one measured in single digits, and the distance is effectively computed on that feature alone.

Worked example

Classifying a new point with k = 3

Training points: \(A(1,1)\) class A, \(B(2,2)\) class A, \(C(3,1)\) class B, \(D(5,5)\) class B. New point \(P(3,2)\).

PointDistance from P(3,2)Class
A(1,1)\(\sqrt{4+1} = 2.236\)A
B(2,2)\(\sqrt{1+0} = 1.000\)A
C(3,1)\(\sqrt{0+1} = 1.000\)B
D(5,5)\(\sqrt{4+9} = 3.606\)B

The three nearest are B (1.000, class A), C (1.000, class B) and A (2.236, class A). Vote: A gets 2, B gets 1, so predict class A.

Note the tie between B and C. Breaking ties by distance is arbitrary here; some implementations prefer odd \(k\) precisely to avoid vote ties.

Choosing k

kEffect
k = 1Decision boundary hugs every point — zero training error, high variance, very sensitive to noise
Large kBoundary smooths out; eventually everything is predicted as the majority class — high bias
Rule of thumbStart at \(\sqrt{n}\) and tune on the validation set; prefer odd values for two-class problems
The curse of dimensionality

As the number of features grows, points that seemed close become far apart — in high dimensions the ratio of nearest to farthest neighbour distance approaches 1, so "nearest" stops meaning anything. KNN degrades badly beyond roughly 10–20 features unless you reduce dimensionality first. This is the standard exam criticism of KNN.

Check your understanding

What happens to KNN as k increases toward n?
With k = n every query's neighbourhood is the entire training set, so the vote is the global class distribution and every prediction is the majority class. That is maximum bias and minimum variance — the opposite failure from k = 1.
