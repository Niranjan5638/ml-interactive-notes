Classification by probability

Instead of drawing a boundary through the feature space, naive Bayes asks a direct question: given these feature values, which class is more probable? It answers with Bayes' theorem and one very strong assumption.

\[ P(C_k \mid x) = \frac{P(x \mid C_k)\,P(C_k)}{P(x)} \]
TermNameWhere it comes from
\(P(C_k \mid x)\)PosteriorWhat we want — probability of the class given the features
\(P(x \mid C_k)\)LikelihoodEstimated from training data, per class
\(P(C_k)\)PriorClass frequency in the training data
\(P(x)\)EvidenceThe same for every class, so it cancels when comparing

Because the denominator is identical for all classes, classification only needs the numerator:

\[ \hat{y} = \arg\max_k \; P(C_k)\prod_j P(x_j \mid C_k) \]

The naive assumption

Conditional independence

The features are assumed independent of each other given the class. This lets the joint likelihood factorise into a product of one-dimensional terms, which is why the model needs so little data and is so fast.

The assumption is almost always false — humidity and outlook are not independent in weather data. The remarkable empirical fact is that classification often still works, because the model only needs the correct class to have the highest score, not the scores themselves to be accurate.

Worked example — the Play Tennis dataset

Predict for Outlook = Sunny, Temperature = Cool, Humidity = High, Wind = Strong

Fourteen training rows: 9 Yes, 5 No. So \(P(\text{Yes}) = 9/14\) and \(P(\text{No}) = 5/14\).

Likelihoods from the frequency tables (denominators are class counts, not 14):

No is about 6.5 times larger, so predict No.

Normalising the two scores gives \(P(\text{Yes}) = 0.00529/0.03958 = 0.134\) and \(P(\text{No}) = 0.866\) — a genuine probability, not just a ranking.

The zero-frequency problem

If a feature value never appears with a class in training, its likelihood is zero, and the product collapses to zero regardless of everything else. One unseen combination destroys the prediction.

Laplace smoothing fixes it by adding a small count to every cell:

\[ P(x_j \mid C_k) = \frac{\text{count}(x_j, C_k) + \alpha}{\text{count}(C_k) + \alpha \cdot |V_j|} \]

where \(|V_j|\) is the number of distinct values of feature \(j\). With \(\alpha = 1\) no probability is ever exactly zero.

Continuous features

The frequency-table approach only works for categorical features. For a continuous feature, assume it is normally distributed within each class and use the density:

\[ P(x \mid C_k) = \frac{1}{\sqrt{2\pi\sigma_k^2}}\exp\left(-\frac{(x-\mu_k)^2}{2\sigma_k^2}\right) \]

Estimate \(\mu_k\) and \(\sigma_k\) from the training rows of class \(k\). This is Gaussian naive Bayes.

Implementation

Pythonnaive_bayes.py
from collections import Counter, defaultdict


def train(rows, labels):
    """rows: list of dicts of feature -> value. Returns priors and likelihoods."""
    priors = Counter(labels)
    counts = defaultdict(Counter)
    totals = Counter()
    values = defaultdict(set)

    for row, label in zip(rows, labels):
        totals[label] += 1
        for f, v in row.items():
            counts[(label, f)][v] += 1
            values[f].add(v)

    return priors, counts, totals, values


def predict(row, model, alpha=1.0):
    """Returns {class: score}. alpha=1 gives Laplace smoothing."""
    priors, counts, totals, values = model
    scores = {}
    n = sum(priors.values())

    for label in priors:
        score = priors[label] / n                    # prior
        for f, v in row.items():
            num = counts[(label, f)][v] + alpha
            den = totals[label] + alpha * len(values[f])
            score *= num / den                       # likelihood
        scores[label] = score
    return scores

Exam trap

The likelihood denominators are the class counts (9 and 5), not the dataset size (14). Writing \(2/14\) instead of \(2/9\) for "Sunny given Yes" is the single most common error in this question, and it is easy to avoid by asking "out of how many Yes days?"

Check your understanding

Why is Laplace smoothing needed?
Because the likelihoods are multiplied, one factor of zero annihilates the score no matter how strong the rest of the evidence. Adding a small count to every cell guarantees no factor is ever exactly zero.

Splitting the feature space

A decision tree asks a sequence of yes/no questions about the features, and each leaf carries a predicted class. Learning means choosing which question to ask at each node — and "best" is defined by how much the split reduces impurity.

Entropy

\[ H(S) = -\sum_{i} p_i \log_2 p_i \]

Entropy measures how mixed a set of labels is. For two classes with proportion \(p\):

  • All one class (\(p = 1\) or \(0\)): \(H = 0\). Pure, no uncertainty.
  • 50/50: \(H = 1\). Maximum uncertainty for two classes.

Entropy explorer

Information gain

\[ \text{IG}(S, A) = H(S) - \sum_{v \in \text{values}(A)} \frac{|S_v|}{|S|} H(S_v) \]

In words: the entropy before the split, minus the weighted average entropy after it. That difference is the information the question gave you. ID3 picks the attribute with the largest gain, then recurses on each branch.

Worked example — the Tennis root node

Choosing the first split

14 rows, 9 Yes and 5 No.

Root entropy: \(H(S) = -\frac{9}{14}\log_2\frac{9}{14} - \frac{5}{14}\log_2\frac{5}{14} = 0.9403\)

Split on Outlook: Sunny (5 rows: 2 Yes, 3 No), Overcast (4: 4 Yes, 0 No), Rain (5: 3 Yes, 2 No).

\(H(\text{Sunny}) = 0.9710\), \(H(\text{Overcast}) = 0\), \(H(\text{Rain}) = 0.9710\)

Weighted: \(\frac{5}{14}(0.9710) + \frac{4}{14}(0) + \frac{5}{14}(0.9710) = 0.6936\)

\(\text{IG}(\text{Outlook}) = 0.9403 - 0.6936 = \mathbf{0.2467}\)

All four attributes:

Outlook0.247
Humidity0.152
Wind0.048
Temperature0.029

Outlook wins, so it becomes the root. Recurse on each branch: the Overcast branch is pure (all Yes), so it becomes a leaf immediately.

Gini impurity

\[ \text{Gini}(S) = 1 - \sum_i p_i^2 \]

An alternative impurity measure used by CART. It is cheaper to compute — no logarithms — and in practice picks almost the same splits.

The same split scored with Gini

Root: \(1 - (9/14)^2 - (5/14)^2 = 0.4592\)

Branches: Sunny \(1 - (2/5)^2 - (3/5)^2 = 0.48\); Overcast \(1 - 1^2 - 0 = 0\); Rain \(0.48\).

Weighted: \(\frac{5}{14}(0.48) + \frac{4}{14}(0) + \frac{5}{14}(0.48) = 0.3429\)

Gini gain \(= 0.4592 - 0.3429 = \mathbf{0.1163}\)

Different number, same ranking: Outlook is still the best split. Entropy and Gini disagree only rarely, and when they do the effect on accuracy is small.

Pruning

An unconstrained tree grows until every leaf is pure, which memorises the training data. Two remedies:

  • Pre-pruning — stop early: limit depth, require a minimum number of samples per leaf, or refuse splits whose gain is below a threshold.
  • Post-pruning — grow the full tree, then remove branches that do not improve validation accuracy. More expensive, usually better.
Why accuracy alone picks bad trees

Information gain is biased toward attributes with many distinct values. An ID column would have a gain of 1.0 — it splits every row into its own pure leaf — and would be chosen as the root every time, while being completely useless. That is why real implementations also require a minimum samples-per-leaf.

Check your understanding

A node contains 10 positives and 10 negatives. What is its entropy?
With p = q = 0.5: H = −(0.5 log₂ 0.5 + 0.5 log₂ 0.5) = −(0.5(−1) + 0.5(−1)) = 1 bit. For two classes, entropy is maximised at a 50/50 split and is 0 when the node is pure.

The laziest classifier

KNN does no training at all. It stores the entire dataset and, at prediction time, finds the \(k\) closest training points and takes a vote. That is the whole algorithm.

Algorithm
  1. Store all training points and their labels.
  2. For a new point, compute the distance to every stored point.
  3. Take the \(k\) smallest distances.
  4. Classification: majority vote among their labels. Regression: average their values.

This is called a lazy learner: it defers all work to prediction time. Training is \(O(1)\), but each prediction costs \(O(n \cdot d)\) for \(n\) points in \(d\) dimensions.

The distance metric

\[ d(a,b) = \sqrt{\sum_{j=1}^{d}(a_j - b_j)^2} \]

Euclidean distance. Because it sums squared differences across features, features must be scaled first — otherwise a feature measured in thousands dominates one measured in single digits, and the distance is effectively computed on that feature alone.

Worked example

Classifying a new point with k = 3

Training points: \(A(1,1)\) class A, \(B(2,2)\) class A, \(C(3,1)\) class B, \(D(5,5)\) class B. New point \(P(3,2)\).

PointDistance from P(3,2)Class
A(1,1)\(\sqrt{4+1} = 2.236\)A
B(2,2)\(\sqrt{1+0} = 1.000\)A
C(3,1)\(\sqrt{0+1} = 1.000\)B
D(5,5)\(\sqrt{4+9} = 3.606\)B

The three nearest are B (1.000, class A), C (1.000, class B) and A (2.236, class A). Vote: A gets 2, B gets 1, so predict class A.

Note the tie between B and C. Breaking ties by distance is arbitrary here; some implementations prefer odd \(k\) precisely to avoid vote ties.

Choosing k

kEffect
k = 1Decision boundary hugs every point — zero training error, high variance, very sensitive to noise
Large kBoundary smooths out; eventually everything is predicted as the majority class — high bias
Rule of thumbStart at \(\sqrt{n}\) and tune on the validation set; prefer odd values for two-class problems
The curse of dimensionality

As the number of features grows, points that seemed close become far apart — in high dimensions the ratio of nearest to farthest neighbour distance approaches 1, so "nearest" stops meaning anything. KNN degrades badly beyond roughly 10–20 features unless you reduce dimensionality first. This is the standard exam criticism of KNN.

Implementation

Pythonknn.py
from collections import Counter
from math import sqrt


def knn_predict(train_X, train_y, query, k=3):
    """Majority vote among the k nearest training points."""
    distances = []
    for x, label in zip(train_X, train_y):
        d = sqrt(sum((a - b) ** 2 for a, b in zip(x, query)))
        distances.append((d, label))

    distances.sort(key=lambda t: t[0])
    nearest = [label for _, label in distances[:k]]
    return Counter(nearest).most_common(1)[0][0]


if __name__ == "__main__":
    X = [(1, 1), (2, 2), (3, 1), (5, 5)]
    y = ["A", "A", "B", "B"]
    print(knn_predict(X, y, (3, 2), k=3))   # A

Check your understanding

What happens to KNN as k increases toward n?
With k = n every query's neighbourhood is the entire training set, so the vote is the global class distribution and every prediction is the majority class. That is maximum bias and minimum variance — the opposite failure from k = 1.
