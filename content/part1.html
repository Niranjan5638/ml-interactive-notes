How the subject divides

Every algorithm in this course answers one of two questions, and the answer determines which family it belongs to. If the data comes with the right answer attached, you are doing supervised learning; if not, unsupervised. Within each, the kind of answer you want splits it further: a number, a label, or a group.

The one naming trap worth fixing now

Logistic regression is a classification algorithm. The name is a historical accident — it fits a linear model and then passes it through a sigmoid to produce a probability, and the decision is made by thresholding that probability. It is in Module 3, not Module 2, and if an exam asks you to classify algorithms by task, putting it under regression is the classic error.

What it means to learn from data

Traditional programming takes rules and data and produces answers. Machine learning inverts it: you supply examples of inputs and the answers you want, and the algorithm produces the rules. That inversion is the entire idea, and everything else in the course is machinery for doing it reliably.

Definition — learning

A program is said to learn from experience \(E\) with respect to task \(T\) and performance measure \(P\) if its performance at \(T\), measured by \(P\), improves with experience \(E\).

Concretely, for a spam filter: the task \(T\) is classifying email, the experience \(E\) is a set of emails already labelled spam or not, and the measure \(P\) is the fraction correctly classified on email it has never seen. Note the last clause — that is the part people get wrong.

Supervised learning splits again by the type of the label. If the label is a real number — price, temperature, run time — the task is regression. If it is a category — spam or not, benign or malignant, cat or dog — the task is classification. This distinction decides which loss function you use and which metrics you report, so it is worth being able to state it precisely.

The anatomy of a learning problem

Five objects appear in every supervised learning problem, and an exam answer that names them will usually earn the marks for the setup.

  1. Features \(x\) — the measured inputs, usually a vector. One row of your table is one example.
  2. Label \(y\) — the answer for that row. \(y \in \mathbb{R}\) for regression, \(y \in \{0,1,\ldots\}\) for classification.
  3. Hypothesis \(h_\theta(x)\) — a family of functions with parameters \(\theta\), chosen in advance.
  4. Loss function \(L(h_\theta(x), y)\) — a number saying how wrong one prediction is.
  5. Cost function \(J(\theta)\) — the loss averaged over the whole training set. Learning means finding \(\theta\) that minimises it.

The choice of hypothesis family is the modeller's decision and it determines what the model can ever represent. A straight line cannot represent a curve no matter how long you train it — that is inductive bias, and chapter 4 shows why it is a feature rather than a flaw.

The workflow, and where it goes wrong

  1. State the task. Regression or classification? What does one row represent?
  2. Split the data. Training set to fit parameters, validation set to tune choices, test set to report one final number.
  3. Fit on the training set. Minimise \(J(\theta)\).
  4. Tune on the validation set. Never on the test set.
  5. Report on the test set. Once.
The mistake that invalidates an entire project

If you tune anything — learning rate, \(k\), tree depth, number of clusters — by looking at test-set performance, the test set has become part of training and your reported number is optimistic. This is called data leakage, and it is the single most common way machine-learning results turn out to be wrong. The validation set exists precisely so the test set is touched once.

Worked example — stating a problem properly

Predict whether a loan applicant will default.

Task: binary classification. One row: one applicant. Features: income, existing debt, credit history length, employment years. Label: defaulted within 12 months (1) or not (0). Hypothesis: a logistic model — chapter 5. Loss: log-loss. Metric: recall on the default class, because missing a default costs far more than refusing a good applicant.

Note the last line. The metric is a business decision, not a mathematical one, and choosing accuracy instead would be wrong: with a 5 % default rate, predicting "nobody defaults" scores 95 % accuracy and is useless.

Check your understanding

Predicting the selling price of a used car from its age, mileage and brand is which kind of problem?
The label is a price — a continuous real number, not a category. Predicting a quantity is regression; predicting which category something falls into is classification. The distinction decides the loss function (squared error rather than log-loss) and the metrics (R² rather than F1).
Why does a separate validation set exist?
Every decision made by looking at a dataset leaks information from it into the model. If you tuned hyperparameters against the test set, the test score is no longer an estimate of performance on unseen data. The validation set absorbs that tuning so the test set stays untouched until the end.

The hypothesis

Start with the simplest possible model: a straight line.

\[ h_\theta(x) = \theta_0 + \theta_1 x \]

\(\theta_1\) is the slope — how much the output changes per unit of input — and \(\theta_0\) is the intercept, the prediction when \(x = 0\). The subscript on \(h\) is there to remind you that the function is not fixed: it is a whole family of lines, and learning means choosing which member of that family to keep.

Why a line, and not something more flexible

Because it is the model with the least inductive bias that is still useful: it assumes only that the relationship is monotone and additive. If the truth is a curve, a line will underfit — but a line that underfits is honest about it, and the residuals tell you to move on. Starting with the most flexible model available hides errors instead of revealing them.

The cost function

For each example, the residual is the gap between prediction and truth: \(h_\theta(x_i) - y_i\). We need a single number summarising all the residuals, and the choice is the mean squared error:

\[ J(\theta_0, \theta_1) = \frac{1}{n}\sum_{i=1}^{n}\bigl(h_\theta(x_i) - y_i\bigr)^2 \]

Squaring does three things: it makes every term non-negative so errors cannot cancel, it penalises large errors much more than small ones, and — the reason it is preferred over absolute value — it makes the function differentiable everywhere, which gradient descent needs.

Worked example — evaluating the cost by hand

Data: \((1,2), (2,3), (3,5)\). Take the starting guess \(\theta_0 = 0, \theta_1 = 0\).

Predictions: \(0, 0, 0\). Residuals: \(-2, -3, -5\).

\(J = \frac{1}{3}\bigl(4 + 9 + 25\bigr) = \frac{38}{3} = 12.667\).

Now try \(\theta_0 = 0.333, \theta_1 = 1.5\), which turns out to be the least-squares optimum. Predictions: \(1.833, 3.333, 4.833\). Residuals: \(-0.167, 0.333, 0.167\).

\(J = \frac{1}{3}\bigl(0.0278 + 0.1111 + 0.0278\bigr) = \frac{0.1667}{3} = 0.0556\).

The cost fell from 12.667 to 0.056 — a factor of 228.

The gradient

To descend, we need the direction of steepest increase, which is the vector of partial derivatives. Differentiating \(J\) with respect to each parameter:

\[ \frac{\partial J}{\partial \theta_0} = \frac{2}{n}\sum_{i=1}^{n}\bigl(h_\theta(x_i) - y_i\bigr) \qquad \frac{\partial J}{\partial \theta_1} = \frac{2}{n}\sum_{i=1}^{n}\bigl(h_\theta(x_i) - y_i\bigr)\,x_i \]

Read them carefully: both are averages of the residual. The second is weighted by \(x_i\), which makes intuitive sense — if a large \(x\) produced a large error, the slope is the parameter at fault, so the slope gets the larger correction.

Worked example — one gradient step

Same data \((1,2),(2,3),(3,5)\), starting at \(\theta_0 = 0, \theta_1 = 0\), with learning rate \(\alpha = 0.01\).

Residuals are \(-2, -3, -5\).

\(\frac{\partial J}{\partial \theta_0} = \frac{2}{3}(-10) = -6.667\)

\(\frac{\partial J}{\partial \theta_1} = \frac{2}{3}\bigl((-2)(1) + (-3)(2) + (-5)(3)\bigr) = \frac{2}{3}(-23) = -15.333\)

Update: \(\theta_0 = 0 - 0.01(-6.667) = 0.0667\), and \(\theta_1 = 0 - 0.01(-15.333) = 0.1533\).

Both parameters moved in the positive direction because both gradients were negative — the update always steps against the gradient.

The update rule

Repeat until the cost stops falling:

\[ \theta_j := \theta_j - \alpha\,\frac{\partial J}{\partial \theta_j} \quad \text{for } j = 0,1 \]

The learning rate \(\alpha\) controls the step size, and it is the parameter that most often breaks a run. Too small and convergence takes forever; too large and the cost diverges — the steps overshoot the minimum and land further up the opposite wall each time.

The mistake in the update

Both parameters must be updated simultaneously, using the gradients computed before either is changed. If you update \(\theta_0\) first and then compute the gradient for \(\theta_1\) using the new \(\theta_0\), you are running a different algorithm. Compute both gradients, store them, then apply both.

Three practical notes

  1. Feature scaling. If one feature ranges over thousands and another over single digits, the cost surface becomes a long thin valley and gradient descent zig-zags. Standardising features fixes it.
  2. Batch versus stochastic. Batch gradient descent uses all \(n\) examples per step — accurate but slow. Stochastic uses one example per step — noisy but fast. Mini-batch is the compromise everyone actually uses.
  3. Closed form versus iterative. For linear regression the exact solution exists: \(\theta = (X^\top X)^{-1}X^\top y\). Gradient descent is used because the same machinery extends to models where no closed form exists, such as logistic regression and neural networks.

Check your understanding

Gradient descent with too large a learning rate typically causes what?
Each step moves distance α times the gradient. If α is large enough that a step overshoots the minimum and lands higher on the opposite side, the next gradient is larger still, so the following step overshoots further. The cost grows without bound rather than settling.
Why is squared error preferred to absolute error for the cost function here?
Absolute error has a kink at zero, where the derivative is undefined, so gradient descent has no direction to step in there. Squared error is smooth everywhere. Note the third option is exactly backwards — squaring makes the cost more sensitive to outliers, which is why MAE exists as an alternative.
