Why one number is not enough

A regression model makes a real number for every input, so it is almost never exactly right. The metrics below all summarise the residuals — but they summarise different things, and choosing the wrong one lets a bad model look good.

Mean squared error

\[ \text{MSE} = \frac{1}{n}\sum_{i=1}^{n}(y_i - \hat{y}_i)^2 \]

Same quantity as the cost function in chapter 2. Its units are the square of the target's units, so an MSE of 9 on prices in rupees means rupees-squared — not directly interpretable. Its virtue is that it penalises large errors heavily.

Mean absolute error

\[ \text{MAE} = \frac{1}{n}\sum_{i=1}^{n}|y_i - \hat{y}_i| \]

Same units as the target, so directly interpretable: "on average we are off by ₹4,200". It weights every error in proportion to its size, which makes it robust to outliers — one wildly wrong prediction moves MAE by its own size, not its square.

Root mean squared error

\[ \text{RMSE} = \sqrt{\text{MSE}} \]

This exists purely to undo the squaring. It has the same units as the target, like MAE, but still penalises large errors quadratically. The practical rule: RMSE ≥ MAE always, and the size of the gap tells you how concentrated the errors are. If RMSE and MAE are close, errors are uniform; if RMSE is much larger, a few large errors dominate.

Coefficient of determination

\[ R^2 = 1 - \frac{SS_{res}}{SS_{tot}}, \qquad SS_{res} = \sum (y_i - \hat{y}_i)^2, \qquad SS_{tot} = \sum (y_i - \bar{y})^2 \]

\(SS_{tot}\) is the error of the dumbest possible model — always predicting the mean. \(SS_{res}\) is your model's error. So \(R^2\) answers: how much of the variance did I explain, compared to just guessing the average?

  • \(R^2 = 1\) — perfect prediction.
  • \(R^2 = 0\) — no better than predicting the mean.
  • \(R^2 < 0\) — worse than predicting the mean. This is possible on test data and is always a red flag.
Worked example — all four on one dataset

Data: \((1,2), (2,3), (3,5)\). Fitted model: \(\hat{y} = 0.333 + 1.5x\).

Predictions: 1.833, 3.333, 4.833. Residuals: 0.167, −0.333, 0.167. Mean of \(y\): \(\bar{y} = 3.333\).

Exam trap

\(R^2\) can be negative. Students often assume it is bounded in \([0,1]\), but that is only true if the model is fitted on the same data it is evaluated on. On a held-out test set, a model worse than the mean gives \(R^2 < 0\). If a question asks for the possible range, the answer is \((-\infty, 1]\).

Check your understanding

A model has RMSE = 4.1 and MAE = 1.9. What does the gap tell you?
RMSE squares before averaging, so it is dragged up disproportionately by large residuals, while MAE is not. A gap this wide means the error distribution has a heavy tail: a handful of badly wrong predictions among many good ones. MAE reports the typical error, RMSE reports the worst of it.

Bias and variance defined

The error of a model has two sources, and they pull in opposite directions.

Definitions

Bias is error from wrong assumptions in the model — the gap between the average prediction and the truth. A straight line fitted to a curve has high bias.

Variance is error from sensitivity to the particular training sample — how much the fitted model would change if you retrained on different data. A very flexible model has high variance.

The decomposition, for squared error, is:

\[ \text{Expected error} = \text{Bias}^2 + \text{Variance} + \text{Irreducible noise} \]

The third term is a floor you cannot beat — no model can predict randomness. The first two are what you trade.

Worked example — spotting it from the numbers

Model A: training \(R^2 = 0.62\), test \(R^2 = 0.60\). Model B: training \(R^2 = 0.99\), test \(R^2 = 0.58\).

A underfits. Both scores are mediocre and nearly equal — the model is not flexible enough, and more data will not help. Add features or a more expressive hypothesis.

B overfits. Training is near-perfect but test is no better than A. The model has memorised the training set. The gap is the variance, and the remedies are more data, a simpler model, or regularisation.

Regularisation

Regularisation adds a penalty for large parameters to the cost function. Large coefficients mean the model is leaning hard on particular features, which is exactly what overfitting looks like.

\[ J(\theta) = \underbrace{\frac{1}{n}\sum (h_\theta(x_i) - y_i)^2}_{\text{fit the data}} + \underbrace{\lambda\,R(\theta)}_{\text{stay simple}} \]

The hyperparameter \(\lambda\) sets the trade. \(\lambda = 0\) recovers ordinary regression; large \(\lambda\) forces every coefficient toward zero and the model toward underfitting.

NamePenalty \(R(\theta)\)What it does to coefficients
Ridge (L2)\(\sum \theta_j^2\)Shrinks all coefficients smoothly toward zero, never exactly to zero
Lasso (L1)\(\sum |\theta_j|\)Drives some coefficients exactly to zero — performs feature selection
Elastic Net\(\alpha\sum|\theta_j| + (1-\alpha)\sum\theta_j^2\)Both: selection plus stability when features are correlated
Why L1 produces exact zeros and L2 does not

Picture the penalty as a constraint region: for L2 it is a circle, for L1 it is a diamond with corners on the axes. The solution sits where the error contours first touch that region. A circle has no corners, so contact is almost always at a smooth point with both coefficients non-zero. A diamond has sharp corners on the axes, and contours tend to reach a corner first — and a corner means one coefficient is exactly zero. That is the whole geometric argument, and it is worth being able to sketch.

Do not penalise the intercept

\(\theta_0\) is normally left out of the penalty. Shrinking the intercept pulls every prediction toward zero, which is meaningless if your target's mean is far from zero. Penalise the slopes, not the offset.

Check your understanding

You need a model that also tells you which features are irrelevant. Which penalty do you use?
A coefficient of exactly zero removes that feature from the model entirely, which is feature selection. Ridge shrinks coefficients toward zero but never reaches it, so every feature stays in. Elastic Net can do it too, but Lasso is the direct answer.

Why linear regression cannot be reused

Suppose you want to predict whether a tumour is malignant (1) or benign (0). Fitting a line gives predictions like 0.3 or 1.4 — numbers that are not probabilities and can fall outside \([0,1]\) entirely. Worse, the fit is dominated by points far from the boundary, which is the opposite of what a classifier needs.

What we want is a model whose output is always a valid probability, and whose decision is made by thresholding that probability.

The sigmoid

\[ \sigma(z) = \frac{1}{1 + e^{-z}}, \qquad h_\theta(x) = \sigma(\theta_0 + \theta_1 x) \]

The sigmoid squashes any real number into \((0,1)\): \(z = 0\) gives 0.5, large positive \(z\) approaches 1, large negative approaches 0. So the linear part decides which side and how confidently, and the sigmoid converts that into a probability.

Odds and log-odds

The model is linear in the log-odds, not in the probability:

\[ \log\frac{p}{1-p} = \theta_0 + \theta_1 x \]

This is worth understanding rather than memorising. A coefficient \(\theta_1 = 0.7\) means that a one-unit increase in \(x\) multiplies the odds by \(e^{0.7} \approx 2.01\) — it doubles them. That is a statement you can put in a report; "the probability increases by 0.7" would be meaningless since probabilities are capped at 1.

The decision boundary

Predict 1 when \(h_\theta(x) \ge 0.5\), which happens exactly when \(\theta_0 + \theta_1 x \ge 0\). So the boundary is where the linear part is zero — a point in one dimension, a line in two, a hyperplane beyond.

Worked example — a prediction by hand

Model: \(h(x) = \sigma(-4 + 2x)\). Classify \(x = 3\).

\(z = -4 + 2(3) = 2\). \(h = \sigma(2) = \frac{1}{1+e^{-2}} = \frac{1}{1+0.1353} = 0.8808\).

Since 0.8808 ≥ 0.5, predict class 1, with 88 % confidence.

The boundary is at \(-4 + 2x = 0\), so \(x = 2\): below 2 predict 0, above 2 predict 1.

The cost function, and why not squared error

Using squared error with a sigmoid gives a non-convex cost — it has multiple local minima, and gradient descent can settle in the wrong one. The standard choice is log-loss (binary cross-entropy):

\[ J(\theta) = -\frac{1}{n}\sum_{i=1}^{n}\Bigl[y_i\log h_\theta(x_i) + (1-y_i)\log\bigl(1-h_\theta(x_i)\bigr)\Bigr] \]

Read it as a switch. When \(y = 1\) the second term vanishes and the cost is \(-\log h\) — which is 0 if the prediction was 1 and grows without bound as the prediction approaches 0. When \(y = 0\) the first term vanishes and the cost is \(-\log(1-h)\), symmetric. Confidently wrong predictions are punished enormously; that is what makes it convex with the sigmoid.

Worked example — the cost of one prediction

With \(x = 3\), \(y = 1\), and \(h = 0.8808\):

\(J = -\log(0.8808) = 0.1269\).

Had the model been confidently wrong — \(h = 0.05\) with \(y = 1\) — the cost would be \(-\log(0.05) = 2.996\), roughly 24 times larger. That steep penalty is what drives the parameters away from confident errors.

The gradient

Remarkably, the update rule has exactly the same shape as linear regression:

\[ \theta_j := \theta_j - \alpha \sum_{i=1}^{n}\bigl(h_\theta(x_i) - y_i\bigr)x_{ij} \]

The derivation differs completely, but the result is the residual times the feature. This is not a coincidence — it follows from using the canonical link function for the Bernoulli distribution.

More than two classes

Replace the sigmoid with the softmax, which turns a vector of scores into a probability distribution over \(k\) classes:

\[ \text{softmax}(z)_i = \frac{e^{z_i}}{\sum_{j} e^{z_j}} \]

Binary logistic regression is the special case \(k = 2\). The loss becomes categorical cross-entropy.

Check your understanding

In \(h(x) = \sigma(-4 + 2x)\), what does the coefficient 2 mean?
Logistic regression is linear in the log-odds, so a unit increase in x adds 2 to the log-odds, which multiplies the odds by e² ≈ 7.39. Option 3 is true but is a fact about the intercept and slope together, not about the coefficient on its own.
