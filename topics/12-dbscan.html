Chapter 12

DBSCAN

Density-based clustering: find dense regions and label the rest as noise.

Clustering by density

k-means asks "which centre is this point nearest?" DBSCAN asks a different question: is this point in a dense region, and if so which dense region is it connected to? That single change fixes four of k-means' five weaknesses at once — it finds the number of clusters itself, it handles non-spherical shapes, it tolerates outliers, and it explicitly labels points that belong to no cluster.

The two parameters

eps (ε) — the radius of a neighbourhood.
MinPts — how many points a neighbourhood must contain for a point to count as dense.

Together they define what "dense" means. Everything else follows.

The definitions

TermDefinition
ε-neighbourhood of pAll points within distance ε of p, including p itself
Core pointA point whose ε-neighbourhood contains at least MinPts points
Border pointNot a core point, but inside the ε-neighbourhood of some core point
Noise pointNeither core nor border — belongs to no cluster
Directly density-reachableq is directly density-reachable from p if q is in p's neighbourhood and p is core
Density-reachableThe transitive closure of the above — a chain of core points
Density-connectedp and q are both density-reachable from some common point o

Note the asymmetry: q can be density-reachable from a core p while p is not reachable from q, because border points are not core. That is why clusters are defined via density-connectivity, which is symmetric.

The algorithm, step by step

  1. Mark every point as unvisited.
  2. Pick an unvisited point \(p\). Compute its ε-neighbourhood.
  3. If the neighbourhood has fewer than MinPts points, mark \(p\) as noise and move on. (It may later be reclassified as a border point if a cluster grows to reach it.)
  4. Otherwise \(p\) is core: start a new cluster and add every point in its neighbourhood to a seed list.
  5. For each point \(q\) in the seed list that is still unvisited: mark it visited, compute its neighbourhood, and if \(q\) is itself core, add its neighbours to the seed list. Every point reached joins the current cluster.
  6. When the seed list is exhausted, the cluster is complete. Return to step 2 for the next unvisited point.

The cost is \(O(n^2)\) in the worst case because every neighbourhood is a full scan. With a spatial index (a k-d tree) the neighbourhood queries become \(O(\log n)\), giving \(O(n\log n)\).

Solved example 1 — eps = 1.5, MinPts = 3

Nine points in two dimensions

A(0,0), B(1,0), C(0,1), D(1,1), I(2.5,0), H(4.5,0), E(5,5), F(5.5,5), G(6,5).

Step 1 — compute every ε-neighbourhood. This is the whole problem; the algorithm is bookkeeping after it.

PointPoints within 1.5CountType
A(0,0)A, B, C, D4core
B(1,0)A, B, C, D, I5core
C(0,1)A, B, C, D4core
D(1,1)A, B, C, D4core
I(2.5,0)I, B2border
H(4.5,0)H1noise
E(5,5)E, F, G3core
F(5.5,5)E, F, G3core
G(6,5)E, F, G3core

Step 2 — the distances that decide it. A few are worth checking by hand:

  • \(d(A,B) = 1.00\), \(d(A,C) = 1.00\), \(d(A,D) = \sqrt2 = 1.414\) — all ≤ 1.5, so A's neighbourhood is {A,B,C,D}.
  • \(d(B,I) = |2.5-1| = 1.50\) — exactly ε, so included. This is what makes B's neighbourhood five points rather than four.
  • \(d(I,H) = |4.5-2.5| = 2.00 > 1.5\) — so H is not in I's neighbourhood, and I stays a border point with only two neighbours.
  • \(d(D,I) = \sqrt{1.5^2 + 1^2} = 1.803 > 1.5\) — D does not reach I.

Step 3 — grow the clusters.

Start at A (core). Its neighbourhood {A,B,C,D} seeds cluster 1. Process B — core, so add B's extra neighbour I. Process I — not core, so it joins the cluster but adds nothing further. The seed list empties.

Cluster 1 = {A, B, C, D, I} — four core points plus one border point.

Next unvisited: H. Its neighbourhood is just itself, 1 < 3 → noise.

Next: E (core) → seeds cluster 2 with {E,F,G}. F and G are both core but add nothing new.

Cluster 2 = {E, F, G}.

Result: two clusters, one border point (I), one noise point (H).

The detail students miss

I(2.5,0) is a border point, not core, because its own neighbourhood has only two members. But it still joins cluster 1, because it lies inside the neighbourhood of the core point B. A border point is always reachable from exactly one cluster in practice; if two clusters both reached it, they would be density-connected and would have merged.

Solved example 2 — the same points with eps = 0.9

Showing the sensitivity to ε

Keep MinPts = 3 and shrink ε to 0.9. Recompute the neighbourhoods.

PointPoints within 0.9CountType
A, B, C, Donly itself — every pairwise distance in the square is ≥ 1.01noise
II only (B is 1.5 away)1noise
HH only1noise
E(5,5)E, F (G is 1.0 away, just over ε)2border
F(5.5,5)E, F, G (both 0.5 away)3core
G(6,5)F, G2border

Result: one cluster {E, F, G} — F is core, E and G are border — and six noise points. The entire first group has vanished.

Nothing about the data changed. Only ε did. This is the central practical difficulty with DBSCAN: one global density threshold cannot serve a dataset containing regions of different density.

Choosing eps and MinPts

  • MinPts first. A common rule is \(\text{MinPts} \ge d + 1\) for \(d\) dimensions, or \(2d\). Larger values make the algorithm more tolerant of noise and produce fewer, larger clusters.
  • eps second, from a k-distance plot: for each point compute the distance to its MinPts-th nearest neighbour, sort those distances, and plot them. The "knee" of the curve is a good ε — points beyond the knee are the ones that will be labelled noise.

Strengths and weaknesses

StrengthsWeaknesses
Finds the number of clusters automaticallyOne global ε cannot handle varying density
Handles arbitrary shapes — rings, crescents, chainsStruggles when clusters have very different densities
Explicitly labels noise and outliersVery sensitive to both parameters
Deterministic — same input, same output (except for border-point ties)Degrades in high dimensions, like every distance-based method
Needs no k in advanceCannot cluster data with large density variation at all well
The weakness that motivates chapter 13

Every limitation in the right-hand column above traces to the same cause: ε is global. A radius small enough to separate two nearby dense clusters will call a genuinely-sparse cluster noise, and a radius large enough to catch the sparse cluster will merge the dense ones. OPTICS exists precisely to remove that constraint.

Implementation

Pythondbscan.py
from math import dist

UNVISITED, NOISE, CLUSTER = -2, -1, 0


def region_query(points, p, eps):
    """All indices within eps of points[p], including p itself."""
    return [i for i, q in enumerate(points) if dist(points[p], q) <= eps]


def dbscan(points, eps, min_pts):
    labels = [UNVISITED] * len(points)
    cluster_id = CLUSTER

    for i in range(len(points)):
        if labels[i] != UNVISITED:
            continue

        neighbours = region_query(points, i, eps)
        if len(neighbours) < min_pts:
            labels[i] = NOISE          # may be upgraded to border later
            continue

        labels[i] = cluster_id
        seeds = [n for n in neighbours if n != i]

        j = 0
        while j < len(seeds):
            q = seeds[j]
            if labels[q] == NOISE:
                labels[q] = cluster_id          # border point: reclaim it
            if labels[q] != UNVISITED:
                j += 1
                continue
            labels[q] = cluster_id
            q_neighbours = region_query(points, q, eps)
            if len(q_neighbours) >= min_pts:    # q is core: expand
                seeds.extend(n for n in q_neighbours if n not in seeds)
            j += 1

        cluster_id += 1

    return labels


if __name__ == "__main__":
    pts = [(0,0), (1,0), (0,1), (1,1), (2.5,0), (4.5,0), (5,5), (5.5,5), (6,5)]
    names = ["A","B","C","D","I","H","E","F","G"]
    for name, lab in zip(names, dbscan(pts, eps=1.5, min_pts=3)):
        print(f"{name}: {'noise' if lab == NOISE else 'cluster ' + str(lab)}")
    # A B C D I -> cluster 0 ;  E F G -> cluster 1 ;  H -> noise

Check your understanding

In solved example 1, why is I(2.5,0) a border point rather than noise?
A border point is defined as non-core but within ε of some core point. I's own neighbourhood is {I, B} — only two, below MinPts — so it is not core. But d(B, I) = 1.5 = ε, so I lies in B's neighbourhood, and B is core. That makes I a border point of cluster 1.
Shrinking eps from 1.5 to 0.9 turned the first group entirely into noise. What does this demonstrate?
The square cluster has points about 1.0–1.4 apart; the second cluster's points are 0.5 apart. No single ε can be both large enough for the first and small enough to distinguish the second. This is exactly the limitation OPTICS was designed to remove.
