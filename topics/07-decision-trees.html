Chapter 07

Decision Trees

Splitting the feature space by whichever question reduces impurity the most.

Splitting the feature space

A decision tree asks a sequence of yes/no questions about the features, and each leaf carries a predicted class. Learning means choosing which question to ask at each node — and "best" is defined by how much the split reduces impurity.

Entropy

\[ H(S) = -\sum_{i} p_i \log_2 p_i \]

Entropy measures how mixed a set of labels is. For two classes with proportion \(p\):

  • All one class (\(p = 1\) or \(0\)): \(H = 0\). Pure, no uncertainty.
  • 50/50: \(H = 1\). Maximum uncertainty for two classes.

Entropy explorer

Information gain

\[ \text{IG}(S, A) = H(S) - \sum_{v \in \text{values}(A)} \frac{|S_v|}{|S|} H(S_v) \]

In words: the entropy before the split, minus the weighted average entropy after it. That difference is the information the question gave you. ID3 picks the attribute with the largest gain, then recurses on each branch.

Worked example — the Tennis root node

Choosing the first split

14 rows, 9 Yes and 5 No.

Root entropy: \(H(S) = -\frac{9}{14}\log_2\frac{9}{14} - \frac{5}{14}\log_2\frac{5}{14} = 0.9403\)

Split on Outlook: Sunny (5 rows: 2 Yes, 3 No), Overcast (4: 4 Yes, 0 No), Rain (5: 3 Yes, 2 No).

\(H(\text{Sunny}) = 0.9710\), \(H(\text{Overcast}) = 0\), \(H(\text{Rain}) = 0.9710\)

Weighted: \(\frac{5}{14}(0.9710) + \frac{4}{14}(0) + \frac{5}{14}(0.9710) = 0.6936\)

\(\text{IG}(\text{Outlook}) = 0.9403 - 0.6936 = \mathbf{0.2467}\)

All four attributes:

Outlook0.247
Humidity0.152
Wind0.048
Temperature0.029

Outlook wins, so it becomes the root. Recurse on each branch: the Overcast branch is pure (all Yes), so it becomes a leaf immediately.

Gini impurity

\[ \text{Gini}(S) = 1 - \sum_i p_i^2 \]

An alternative impurity measure used by CART. It is cheaper to compute — no logarithms — and in practice picks almost the same splits.

The same split scored with Gini

Root: \(1 - (9/14)^2 - (5/14)^2 = 0.4592\)

Branches: Sunny \(1 - (2/5)^2 - (3/5)^2 = 0.48\); Overcast \(1 - 1^2 - 0 = 0\); Rain \(0.48\).

Weighted: \(\frac{5}{14}(0.48) + \frac{4}{14}(0) + \frac{5}{14}(0.48) = 0.3429\)

Gini gain \(= 0.4592 - 0.3429 = \mathbf{0.1163}\)

Different number, same ranking: Outlook is still the best split. Entropy and Gini disagree only rarely, and when they do the effect on accuracy is small.

Pruning

An unconstrained tree grows until every leaf is pure, which memorises the training data. Two remedies:

  • Pre-pruning — stop early: limit depth, require a minimum number of samples per leaf, or refuse splits whose gain is below a threshold.
  • Post-pruning — grow the full tree, then remove branches that do not improve validation accuracy. More expensive, usually better.
Why accuracy alone picks bad trees

Information gain is biased toward attributes with many distinct values. An ID column would have a gain of 1.0 — it splits every row into its own pure leaf — and would be chosen as the root every time, while being completely useless. That is why real implementations also require a minimum samples-per-leaf.

Check your understanding

A node contains 10 positives and 10 negatives. What is its entropy?
With p = q = 0.5: H = −(0.5 log₂ 0.5 + 0.5 log₂ 0.5) = −(0.5(−1) + 0.5(−1)) = 1 bit. For two classes, entropy is maximised at a 50/50 split and is 0 when the node is pure.
